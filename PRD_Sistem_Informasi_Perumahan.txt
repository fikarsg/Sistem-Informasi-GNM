PRD - SISTEM INFORMASI PERUMAHAN
Versi 1.0

1. INFORMASI DOKUMEN
Nama Produk      : Sistem Informasi Perumahan
Jenis Produk     : Website Sistem Informasi
Target Pengguna  : Pengurus Perumahan dan Warga
Platform         : Web Responsive (Desktop dan Mobile)
Model Akses      : Login berbasis Role
Role             : Pengurus dan Warga

2. LATAR BELAKANG
Sistem dibuat untuk membantu pengurus perumahan mengelola data rumah, warga,
tagihan air, tagihan sampah, pembayaran, kas masuk, kas keluar, dan laporan
keuangan secara terstruktur dan transparan.

Warga dapat mengakses informasi yang relevan melalui akun masing-masing,
tetapi tidak memiliki hak untuk menambah, mengubah, atau menghapus data
keuangan maupun data operasional.

3. TUJUAN PRODUK
- Digitalisasi administrasi perumahan.
- Mempermudah pengurus mengelola tagihan dan pembayaran.
- Mengetahui rumah yang sudah dan belum membayar.
- Memisahkan dan memantau keuangan air, sampah, dan kas umum.
- Menyediakan laporan keuangan yang mudah dipahami.
- Meningkatkan transparansi informasi kepada warga.
- Menyediakan riwayat transaksi yang jelas.
- Mengurangi pencatatan manual dan kesalahan administrasi.

5. ROLE DAN HAK AKSES

5.1 PENGURUS
Pengurus memiliki akses CRUD (Create, Read, Update, Delete) terhadap data
yang menjadi tanggung jawabnya.

Pengurus dapat:
- Menambah, melihat, mengubah, dan menghapus data rumah.
- Menambah, melihat, mengubah, dan menghapus data warga.
- Membuat dan mengelola tagihan air.
- Membuat dan mengelola tagihan sampah.
- Mencatat pembayaran.
- Mengelola kas masuk.
- Mengelola kas keluar.
- Membuat dan melihat laporan.
- Membuat dan mengelola pengumuman.
- Mengelola akun warga.
- Melihat audit log.

5.2 WARGA
Warga bersifat READ ONLY terhadap informasi sistem.

Warga dapat:
- Melihat dashboard.
- Melihat data rumahnya sendiri.
- Melihat tagihan air rumahnya sendiri.
- Melihat tagihan sampah rumahnya sendiri.
- Melihat riwayat pembayaran rumahnya sendiri.
- Melihat ringkasan keuangan yang dipublikasikan.
- Melihat pengumuman.
- Mengubah informasi profil yang memang diizinkan sistem, jika fitur tersebut
  diaktifkan.

Warga TIDAK dapat:
- Membuat transaksi keuangan.
- Mengubah transaksi keuangan.
- Menghapus transaksi keuangan.
- Membuat tagihan.
- Mengubah nominal tagihan.
- Mengubah status pembayaran.
- Mengubah saldo.
- Mengubah data rumah.
- Mengubah data warga lain.
- Menghapus data.

CATATAN KEAMANAN:
Pembatasan warga harus diterapkan di backend/API, bukan hanya dengan
menyembunyikan tombol pada frontend. Setiap endpoint yang mengubah data
harus memeriksa role dan permission pengguna.

10. TAGIHAN AIR

Sistem mendukung pencatatan tagihan berdasarkan meter air.

Field:
- ID tagihan.
- Rumah.
- Periode.
- Meter awal.
- Meter akhir.
- Pemakaian.
- Tarif.
- Biaya/tagihan.
- Denda (jika ada).
- Total tagihan.
- Jatuh tempo.
- Status pembayaran.
- Catatan.
- Tanggal dibuat.
- Dibuat oleh.

Formula dasar:
Pemakaian = Meter Akhir - Meter Awal

Jika tarif per m3:
Tagihan Dasar = Pemakaian x Tarif

Total Tagihan = Tagihan Dasar + Denda - Potongan (jika ada)

Sistem harus mencegah meter akhir lebih kecil dari meter awal kecuali
pengurus melakukan koreksi dengan alasan yang tercatat.

Fitur opsional yang dapat dipersiapkan:
- Foto meter air.
- Riwayat pemakaian.
- Grafik penggunaan per rumah.

25. KEAMANAN

Minimum:
- Password di-hash.
- Session/token aman.
- Authorization berdasarkan role.
- Backend memvalidasi permission.
- Validasi input.
- Proteksi terhadap SQL injection.
- Proteksi XSS.
- Proteksi CSRF jika menggunakan session-based authentication.
- Rate limiting login/API.
- Backup database berkala.
- Audit log untuk aktivitas penting.
- HTTPS pada production.
- File upload dibatasi tipe dan ukuran.
- Akses file bukti transaksi harus terkontrol.

26. PRIVASI DATA

Data warga merupakan data terbatas.

Aturan:
- Warga hanya dapat mengakses data rumahnya sendiri.
- Warga tidak dapat melihat data pribadi warga lain.
- Warga tidak dapat mengakses endpoint admin.
- Informasi keuangan publik hanya menampilkan data yang memang ditetapkan
  untuk transparansi.
- Dokumen/bukti transaksi tidak boleh dapat diakses publik tanpa otorisasi.

33. BUSINESS RULES

BR-001:
Hanya pengurus yang dapat membuat atau mengubah data keuangan.

BR-002:
Warga hanya memiliki akses READ terhadap informasi keuangan.

BR-003:
Warga hanya dapat melihat tagihan dan pembayaran rumah yang terkait
dengan akunnya.

BR-004:
Warga tidak boleh mengakses data warga lain melalui URL/API.

BR-005:
Tagihan yang sudah lunas tidak boleh diubah secara sembarangan. Perubahan
harus tercatat dalam audit log.

BR-006:
Transaksi keuangan yang sudah tercatat sebaiknya tidak dihapus permanen.
Gunakan pembatalan/VOID.

BR-007:
Saldo dihitung berdasarkan transaksi valid.

BR-008:
Transaksi yang VOID tidak dihitung dalam saldo.

BR-009:
Meter akhir tidak boleh lebih kecil daripada meter awal tanpa proses koreksi.

BR-010:
Setiap transaksi keuangan wajib memiliki tanggal, nominal, kategori, dan
keterangan minimum.

34. NON-FUNCTIONAL REQUIREMENTS

Performa:
- Dashboard harus dapat digunakan dengan nyaman pada koneksi internet
  standar.
- Query laporan harus menggunakan pagination/filter jika data besar.

Responsif:
- Mobile-first untuk warga.
- Desktop/tablet friendly untuk pengurus.

Reliability:
- Backup database rutin.
- Error handling yang jelas.
- Tidak kehilangan transaksi ketika terjadi kegagalan request.

Maintainability:
- Struktur kode modular.
- API dan business logic dipisahkan.
- Validasi terpusat.
- Dokumentasi endpoint.
